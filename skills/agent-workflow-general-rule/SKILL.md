# エージェントチーム共通開発規約

本ドキュメントは、すべての専門エージェント（要件分析、設計、計画、実装、レビュー、QA、修正、統合）が従うべき共通ルールです。

## 1. 基本行動指針

- **最小限かつ安全な変更**: 要求された仕様を満たす最小限のコード変更を行い、不要なリファクタリングや仕様外の機能追加は避ける。
- **可読性と自己文書化**: コード自体が意図を語るように命名（変数・関数・クラス）を明確にし、複雑なロジックには理由（Why）を説明するコメントを残す。
- **後方互換性と破壊的変更の防止**: 既存のAPIやインターフェースを壊さないように配慮する。

## 2. アーキテクチャ・設計方針

- **レイヤードアーキテクチャ（責務の分離）**:
  - ドメイン層（ビジネスロジック・エンティティ）
  - アプリケーション層（ユースケース）
  - インフラ層（DBアクセス、外部API連携）
  - プレゼンテーション層（APIエンドポイント、UI）
- ドメイン層はインフラ層やフレームワークに依存させない（依存関係逆転の原則）。

## 3. コーディング＆テスト規約

- **型安全性の徹底**: TypeScript / Python / Go などの型注釈を省略せず厳格に定義する（`any` の安易な使用禁止）。
- **エラーハンドリング**: 例外を握りつぶさず、呼び出し元に適切なエラー情報を返す。
- **単体テストの必須化**: 新規追加したロジックには必ず対応する単体テスト（Unit Test）を作成し、エッジケースや異常系もカバーする。

## 4. Git & コミット規約 (Conventional Commits)

コミットメッセージは以下のプレフィックスを使用する：

- `feat:` 新機能の追加
- `fix:` バグ修正
- `refactor:` リファクタリング（機能変更なし）
- `test:` テストコードの追加・修正
- `docs:` ドキュメントの変更
- `chore:` ビルド・設定ファイルの変更
